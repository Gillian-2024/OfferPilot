## 1. 需求背景

作者本人应届校招，求职过程高频三动作：拆 JD、改简历、面试复盘。三动作都吃产品思维——拆 JD = 拆需求文档、改简历 = 评审方案对需求、复盘面试 = 复盘答辩。作者本职大厂 AI 策略 PM，个人方法论和知识可直接注入辅导工具，垂类匹配度高。把这三动作做成自用工具，同时作为简历项目展示 AI 产品全栈能力。

## 2. 产品定位

- **是什么**：面向应届生校招的求职辅助 web 工具，用 AI 策略 PM 视角做 JD / 简历 / 面试三能力。
- **为谁**：作者自用为主；架构预留分享（别人登录也能用），不商业化、不获客。
- **形态**：web（响应式 + 可选 PWA），不做 native App。
- **不是什么**：不是简历模板站、不是面试题库、不是求职 SaaS——是个人 AI 辅导工具。

## 3. 目标用户

| 用户 | 场景 |
|---|---|
| 作者本人（主要） | 校招求职全流程自用：拆 JD、改简历、面试前模拟 + 复盘 |
| 分享用户（次要） | 经作者分享登录使用，同等能力，不付费 |

## 4. 核心能力

### 4.1 JD 拆解（3 节点）
输入 JD 原文 → 结构化输出：岗位定位 / 类型 / 硬性要求 / 软素质 / 筛选优先级 / 关键词清单 + 应届校招校准。一次性出结果，无多轮。

### 4.2 简历拆解（4 节点链 + JD 对照）
**与 JD 对照，非独立**——JD 拆解结果作为基线注入简历拆解 2-4 步。
- step1：简历结构化（提取经历段落）
- step2：逐段对 JD 要求（满足 / 部分 / 缺失 + 证据）
- step3：requirement_gaps（维度 / 要求 / 状态 / 证据 / 缺口）
- step4：逐段改写建议（quick_wins 优先）
未拆 JD 时降级"非对照模式"（通用应届生标准）。

### 4.3 面试复盘（SSE 对话 + 模拟追问）
多轮对话：用户答 → AI 模拟面试官追问 → 用户再答。流式输出（SSE）。会话可持久化复盘。

## 5. 差异点

个人 AI 策略 PM 知识 + 记忆注入垂类（应届校招求职辅导）。候选落地：
- system prompt 注入个人方法论（如需求分析方法论）
- RAG 个人知识库（Supabase pgvector）
- few-shot 个人案例

⚠️ 注入方式待确认（见 §9）。

## 6. 产品形态

web 应用，响应式（手机浏览器可用），可选 PWA（装桌面图标）。不做 native App。

## 7. 不做边界

- ❌ 商业化 / 获客 / 支付 / 订阅
- ❌ 多租户 / 团队协作
- ❌ 合规审计（demo 级）
- ❌ native App
- ❌ 简历模板站式海量模板（只做对照改写）

## 8. 技术与部署（摘要，详见 tech-architecture.md）

- 栈：Next.js App Router + Vercel AI SDK v7 + Supabase（PG + Auth + Storage + RLS）+ Vercel
- provider 双轨：本机 自建网关（glm-5.2）/ 上线智谱官方（glm-5.2 无缝）
- 数据：5 表 + RLS 用户隔离
- 部署：Vercel 关联 GitHub，main 自动部署
- 迁移：从现有 Vite + Express MVP（2195 行）迁，可搬资产占大头，路线图 P1-P7
