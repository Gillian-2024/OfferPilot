## 1. 需求背景

作者本人应届校招，求职过程高频三动作：拆 JD、改简历、面试复盘。三动作都吃产品思维——拆 JD = 拆需求文档、改简历 = 评审方案对需求、复盘面试 = 复盘答辩。作者本职大厂 AI 策略 PM，个人方法论和知识可直接注入辅导工具，垂类匹配度高。把这三动作做成自用工具，同时作为简历项目展示 AI 产品全栈能力。

## 2. 产品定位

- **是什么**：面向应届生校招的求职辅助 web 工具，用 AI 策略 PM 视角做 JD 拆解 / 简历拆解 / 面试准备 / 面试复盘 四大能力。
- **为谁**：作者自用为主；架构预留分享（别人登录也能用），不商业化、不获客。
- **形态**：web（响应式 + 可选 PWA），不做 native App。
- **不是什么**：不是简历模板站、不是面试题库、不是求职 SaaS——是个人 AI 辅导工具。

## 3. 目标用户

| 用户 | 场景 |
|---|---|
| 作者本人（主要） | 校招求职全流程自用：拆 JD、改简历、面试前模拟 + 复盘 |
| 分享用户（次要） | 经作者分享登录使用，同等能力，不付费 |

## 4. 核心能力

### 4.1 JD 拆解（3 节点）
输入 JD 原文 → 结构化输出：岗位定位 / 类型 / 硬性要求 / 软素质 / 筛选优先级 / 关键词清单 + 应届校招校准。一次性出结果，无多轮。

### 4.2 简历拆解（4 节点链 + JD 对照）
**与 JD 对照，非独立**——JD 拆解结果作为基线注入简历拆解 2-4 步。
- step1：简历结构化（提取经历段落）
- step2：逐段对 JD 要求（满足 / 部分 / 缺失 + 证据）
- step3：requirement_gaps（维度 / 要求 / 状态 / 证据 / 缺口）
- step4：逐段改写建议（quick_wins 优先）
未拆 JD 时降级"非对照模式"（通用应届生标准）。

### 4.3 面试准备（SSE 对话 + 8 快捷能力）

面试前准备阶段：对话式流式输出（SSE），与面试复盘共用同一组件与顶栏（viewMode 区分）。内置 8 个快捷能力：预测面试题 / 公司定向 / 概念辨析 / 场景分析 / 反问技巧 / 自我介绍 / HR面准备 / 薪资谈判。

### 4.4 面试复盘（SSE 对话 + 模拟追问）
多轮对话：用户答 → AI 模拟面试官追问 → 用户再答。流式输出（SSE）。会话可持久化复盘。

## 5. 差异点

个人 AI 策略 PM 知识 + 记忆注入垂类（应届校招求职辅导）。

**注入方式已定（2026-08-23，已落地）**：system prompt 注入——个人方法论提取式脱敏后注入共享的 AI 策略 PM 人设底座（四能力共用），覆盖三层：

- 需求文档审查方法论（与「JD = 需求文档」同构：铁律 / 歧义门控 / 五维度预检）
- PM 工作思维（六条决策逻辑 / 六条行事准则）
- 教练式带教风格 + 跨领域学习方法论 + 知识域地图

后续扩展（量驱后再做，暂不实现）：RAG 个人知识库（Supabase pgvector）、few-shot 个人案例。

## 9. BYOK 架构下的完美解法

### 核心判断

BYOK 丢的是「模型选择」一个旋钮，不是「约束能力」全部。产品把确定性建在以下三层上，模型再弱也只会降级而非崩溃：

| 层 | 机制 | 目的 |
|---|---|---|
| **输入控制** | 用户内容套 `[user-content]...[/user-content]` 边界防 prompt injection；上下文超限检测，超 128k 截断+提示，不盲扔 | 防止模型被污染或截断 |
| **输出控制** | SSE SSEResult 消费后走 JSON parse + validate，失败重试一次；校验不过放半成品 + 标注「该模型拆分深度不足」，不硬塞 | 守门员不让烂输出出门 |
| **一致性管理** | 推荐模型分级引导（非裸 dropdown）；每次回答携带模型版本信息；成长档案记录质量轨迹 | 让用户选但要被引导 |

### 价值锚点

> BYOK 之下，定义在 prompt 会被抄死；定义在数据流和确定性工程，模型再弱也抄不走。壁垒=岗位库 + 简历轨迹 + 面试记忆——这些流不走。
